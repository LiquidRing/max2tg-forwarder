# max2tg-forwarder

Двусторонний мост между **MAX Messenger** и **Telegram**: каждая группа Telegram
привязывается к одному чату MAX. Всё, что приходит в чат MAX, попадает в группу;
всё, что вы пишете в группе, уходит обратно в MAX — вместе с вложениями, ответами
и правками. Заходить в клиент MAX больше не нужно.

```
   чат MAX  ──►  пользовательская сессия MAX (pyromax)  ──►  мост  ──►  бот Telegram  ──►  группа
   чат MAX  ◄──  пользовательская сессия MAX (pyromax)  ◄──  мост  ◄──  бот Telegram  ◄──  группа
```

## Как это устроено

| Модуль | Роль |
| --- | --- |
| `adapters/max_adapter.py` | пользовательская сессия MAX поверх `pyromax`: приём событий, загрузка и скачивание вложений, справочник чатов |
| `adapters/telegram_adapter.py` | бот Telegram на `aiogram 3`: команды управления, приём сообщений группы, доставка сообщений из MAX |
| `adapters/telegram_userbot.py` | пользовательская сессия на `telethon`: создание групп и папки для `/sync` |
| `bridge.py` | оркестратор: очередь на каждый чат, маршрутизация, ответы, правки, учёт соответствий |
| `models.py` | `NormalizedMessage` / `NormalizedAttachment` — общий язык обеих платформ |
| `storage.py`, `db.py` | SQLite: привязки чатов и соответствия идентификаторов сообщений |
| `util/text.py` | перенос форматирования (жирный, курсив, ссылки, цитаты) в обе стороны |

Адаптеры не знают друг о друге: связывает их только мост, а обмениваются они
нормализованными сообщениями. Вложения скачиваются лениво — только если сообщение
действительно будет доставлено.

## Требования

* Python 3.11+
* [uv](https://docs.astral.sh/uv/)
* аккаунт MAX (мост работает от вашего имени — это пользовательская сессия, не бот)
* бот Telegram из [@BotFather](https://t.me/BotFather)

## Установка

```bash
uv sync
```

Скопируйте `.env.example` в `.env` и заполните `TG_BOT_TOKEN`.

**Важно:** у бота нужно выключить privacy mode, иначе он не увидит сообщения в группе.
В @BotFather: `/mybots` → ваш бот → *Bot Settings* → *Group Privacy* → *Turn off*.
Мост проверяет это при старте и предупреждает в логе и в `/status`.

Если Telegram доступен только через прокси, укажите его в `TG_PROXY` — либо мост
возьмёт адрес из `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` окружения (ни `aiohttp`,
ни Telethon, в отличие от `curl`, системные настройки прокси сами не читают).
Тот же адрес используется и для MTProto-сессии `/sync`; при необходимости его
можно задать отдельно через `TG_USERBOT_PROXY`. Поддерживаются `http://`,
`socks5://` и `socks4://`, в том числе с логином и паролем.

## Запуск

```bash
uv run max2tg
```

или

```bash
uv run python -m max2tg
```

При первом запуске в консоли появится QR-код: отсканируйте его в приложении MAX
(*Настройки → Устройства → Подключить устройство*). Токен сохранится в `tokens.json`
рядом с рабочим каталогом (`STATE_DIR`), повторная авторизация не потребуется.

## Привязка чатов

1. Создайте группу в Telegram и добавьте туда бота.
2. Отправьте `/chats` — бот покажет список ваших чатов MAX с идентификаторами.
3. Отправьте `/bind <max_chat_id>` — группа привязана.

Дальше всё работает само.

| Команда | Что делает |
| --- | --- |
| `/start` | с чего начать: пошаговый онбординг с кнопками |
| `/chats [фильтр]` | список чатов MAX с идентификаторами |
| `/bind [max_chat_id]` | привязать группу к чату MAX; без аргумента — выбор кнопками |
| `/pause`, `/resume` | приостановить и возобновить пересылку, не теряя привязку |
| `/sync [название папки]` | создать группы под все чаты MAX и сложить их в папку |
| `/login [номер]` | вход в свою сессию Telegram (только в личке с ботом), `/login logout` — выход |
| `/selftest [full]` | прогнать проверочные сообщения и отчитаться таблицей |
| `/unbind` | снять привязку |
| `/status` | привязка, аккаунт MAX, состояние связи и счётчик перенесённого |
| `/id` | идентификаторы группы и ваш собственный |
| `/help` | справка |

### Автоматическая раскладка: `/sync`

`/sync` создаёт по супергруппе на каждый чат MAX, зовёт туда бота
администратором, ставит группе аватар чата MAX, привязывает её и складывает всё в папку
(по умолчанию «MAX (СКАМ)», имя можно передать аргументом: `/sync Работа`).
Группа называется так же, как чат в MAX. Аккаунты MAX разделяются папками, а не
префиксами: пока аккаунт один, папка называется как попросили, а со второго
каждый получает свою папку по имени аккаунта (Telegram отводит на название
папки 12 символов, длинное имя обрезается).
Повторный вызов работает как синхронизация: сверяется с фактическим состоянием
групп — чинит устаревшие названия и пропавшие аватары, создаёт недостающие группы,
обновляет состав папки и сообщает о группах, которые стали недоступны.

При первой привязке (и через `/bind`, и через `/sync`) мост переносит в группу
последние сообщения чата MAX — по умолчанию 100, настраивается через
`HISTORY_IMPORT_LIMIT` (0 отключает перенос). Повторный вызов историю не дублирует:
уже перенесённые сообщения отсекаются по таблице соответствий.

Bot API не умеет создавать ни группы, ни папки, поэтому команде нужна
**пользовательская сессия Telegram** — отдельный вход от вашего имени:

1. Получите `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org)
   → *API development tools*.
2. Добавьте в `.env`: `TG_API_ID`, `TG_API_HASH`, `TG_PHONE` — и перезапустите мост.
3. Напишите боту в личку `/login`. Он отправит код в Telegram и попросит прислать
   его **через дефисы**: `1-2-3-4-5`.

   > Telegram аннулирует код, если увидит его в переписке обычным числом — это
   > защита от фишинга. Разделители её обходят. Сообщение с кодом (и с паролем
   > двухфакторной защиты, если он спрошен) бот удаляет сразу после проверки.
   > Отменить вход на любом шаге: `/login cancel`.

4. Отправьте `/sync` — перезапуск не нужен.

Сессия своя у каждого пользователя моста: группы создаются от его имени и
попадают в его список чатов. Строка сессии хранится в базе, зашифрованная
`MASTER_KEY`; `/login logout` стирает её и отключает автосоздание групп. Кто
входить не хочет, обходится ручной раскладкой: создать группу, добавить бота
администратором, выполнить `/bind`.

Тот же вход доступен из консоли — сессия сохранится за первым идентификатором
из `TG_ADMIN_IDS`:

```bash
uv run max2tg login
```

Telegram ограничивает частоту создания групп, поэтому за один вызов создаётся
не больше `SYNC_GROUP_LIMIT` групп (по умолчанию 20) с паузой между ними;
остаток доберёт следующий `/sync`. Бот в созданных группах сразу получает права
администратора — это заодно снимает вопрос privacy mode.

Одна группа Telegram — один чат MAX (привязка взаимно однозначная: повторный
`/bind` заменяет предыдущую связь). Для второго чата MAX создайте вторую группу.

Чтобы командами управления мог пользоваться только вы, укажите свой идентификатор
(его покажет `/id`) в `TG_ADMIN_IDS`.

### Самопроверка: `/selftest`

`/selftest` отправляет в привязанную группу проверочные сообщения от вашего
имени, ждёт, пока мост их разберёт, и присылает таблицу с результатом.
Без аргумента гоняются текст и фотография, `/selftest full` — вся матрица:
форматирование, эмодзи вне BMP, ответ, правка, длинный текст, фото, документ,
голосовое, кружок, GIF и альбом. Направление MAX → Telegram так не проверить:
сервер MAX не присылает мосту его собственные сообщения, поэтому напишите в
чат MAX с телефона — отчёт учтёт входящие за время прогона.

Команды продублированы в меню Telegram (кнопка «/» рядом с полем ввода):
в личке видны команды об аккаунтах, в группах — о привязке и пересылке.
Бот здоровается при добавлении в группу и сразу подсказывает следующий шаг,
а `/unbind` спрашивает подтверждение — снятая по ошибке привязка стоит
повторного переноса истории.

## Что переносится

| | MAX → Telegram | Telegram → MAX |
| --- | --- | --- |
| Текст и форматирование | ✅ (жирный, курсив, подчёркивание, зачёркивание, цитаты, ссылки) | ✅ |
| Фотографии | ✅ | ✅ |
| Видео | ✅ | ✅ |
| Видеосообщения («кружки») | ✅ | ⚠️ (обычным видео с пометкой) |
| Голосовые | ✅ | ⚠️ (файлом с пометкой) |
| Файлы и документы | ✅ | ✅ |
| Аудио | ✅ | ✅ (как файл) |
| GIF / анимации | ✅ | ✅ (как видео) |
| Альбомы | ✅ (собираются в media group) | ✅ (альбом уходит одним сообщением) |
| Стикеры | ✅ (анимированные едут как `.tgs`, статичные — картинкой) | статичные конвертируются в PNG, прочие — файлом |
| Ответы на сообщения | ✅ | ✅ |
| Правки сообщений | ✅ | ✅ (текст) |
| Пересланные сообщения | ✅ (с пометкой об авторе) | ✅ |
| Геопозиция, контакты, опросы | текстовая пометка со ссылкой | текстовая пометка |
| Реакции, удаления | ❌ | ❌ |
| Аватары чатов | ✅ (`/sync` ставит их аватарами групп) | ❌ |

Сообщения из MAX подписываются именем отправителя (жирной первой строкой) —
в групповом чате MAX участников много. В обратную сторону подпись не ставится:
к MAX подключён единственный аккаунт, и отправитель там всегда один.

## Ограничения

* **Bot API отдаёт боту файлы не больше 20 МиБ и принимает не больше 50 МиБ.**
  Всё, что крупнее, не переносится — вместо файла приходит пометка с причиной.
  Это ограничение Telegram, а не моста.
* **MAX не принимает кружки и голосовые от сторонних клиентов.** Сервер
  отвечает `errors.process.attachment.video.not.supported` на любой кодек
  (проверены opus, aac, mp3, h264 baseline), поэтому кружок из Telegram уходит
  обычным видео, а голосовое — файлом; перед вложением идёт пометка
  «⭕ видеосообщение (кружок)» или «🎤 голосовое сообщение». В обратную сторону
  (MAX → Telegram) и то и другое переносится как есть.
* Реакции и удаления сообщений не синхронизируются.
* При правке сообщения переносится только текст: заменить вложение у уже
  отправленного сообщения ни одна из платформ не позволяет.
* Смещения разметки MAX трактуются как UTF-16; если в тексте есть эмодзи вне
  BMP, форматирование может съехать на пару символов. Текст при этом не страдает.
  Способ переноса разметки настраивается: `TG_TO_MAX_FORMATTING=elements|tags|plain`.
* Мост работает от вашей пользовательской сессии MAX. `pyromax` — неофициальная
  библиотека, использующая приватный протокол MAX; администрация сервиса может
  расценить это как нарушение правил и ограничить аккаунт. Риск на вас.

## Развёртывание на сервере

Мост живёт долго, поэтому на сервере его удобно держать службой systemd —
пользовательской, без root:

```bash
# 1. Код и зависимости
scp -r . ubuntu@сервер:~/max2tg-forwarder      # без .venv, .env и state/
ssh ubuntu@сервер 'cd ~/max2tg-forwarder && uv sync --frozen'

# 2. Настройки и состояние (переносить с уже работающей установки — по желанию)
scp .env ubuntu@сервер:~/max2tg-forwarder/.env
scp max2tg.sqlite3 ubuntu@сервер:~/max2tg-forwarder/state/max2tg.sqlite3
scp tokens.json ubuntu@сервер:~/max2tg-forwarder/state/tokens.json
```

В `.env` на сервере укажите `STATE_DIR=./state`, а файл закройте от посторонних:
`chmod 600 .env`. Готовый юнит лежит в [`deploy/max2tg.service`](deploy/max2tg.service) — скопируйте его в `~/.config/systemd/user/max2tg.service`:

```ini
[Unit]
Description=Мост MAX <-> Telegram
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/max2tg-forwarder
ExecStart=%h/.local/bin/uv run --frozen python -u -m max2tg
Environment=PYTHONUNBUFFERED=1
Environment=LANG=C.UTF-8
Restart=always
RestartSec=10
StartLimitIntervalSec=0

[Install]
WantedBy=default.target
```

```bash
loginctl enable-linger $USER          # чтобы служба жила без входа в систему
systemctl --user enable --now max2tg
journalctl --user -u max2tg -f        # журнал
```

Два экземпляра моста одновременно запускать нельзя: Bot API отдаёт обновления
только одному получателю, и сессия MAX тоже одна. Перед запуском на сервере
остановите локальный.

## Настройки

Все параметры перечислены в [`.env.example`](.env.example) с комментариями.
Наиболее полезные:

| Переменная | Назначение |
| --- | --- |
| `TG_BOT_TOKEN` | токен бота (обязательно) |
| `TG_ADMIN_IDS` | кому доступны команды управления |
| `TG_PROXY` | прокси для Bot API; если пусто, берётся из `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` |
| `TG_USERBOT_PROXY` | прокси для MTProto-сессии; если пусто, берётся `TG_PROXY`, затем окружение |
| `MAX_DEVICE_TYPE` | тип устройства сессии MAX: `WEB`, `ANDROID`, `DESKTOP` |
| `MAX_PASSWORD` | пароль, если на аккаунте MAX включена двухфакторная защита |
| `MAX_FORWARD_OWN_MESSAGES` | пересылать ли в Telegram то, что вы пишете из клиента MAX |
| `STATE_DIR` | каталог для `tokens.json` и базы |
| `TG_TO_MAX_FORMATTING` | способ переноса разметки в MAX |
| `TG_API_ID`, `TG_API_HASH`, `TG_PHONE` | пользовательская сессия Telegram для `/sync` |
| `TG_FOLDER_NAME` | название папки по умолчанию (`MAX (СКАМ)`) |
| `SYNC_GROUP_LIMIT`, `SYNC_CREATE_DELAY` | сколько групп создавать за вызов и пауза между ними |
| `HISTORY_IMPORT_LIMIT` | сколько последних сообщений переносить при привязке чата |

Собственные сообщения, отправленные самим мостом, обратно в Telegram не
возвращаются: они отсеиваются по таблице соответствий.

```bash
uv run ruff format . && uv run ruff check --fix .
uv run mypy

```

Тесты не ходят в сеть: проверяются маршрутизация моста, слой хранения,
